<h1 align="center">音纽 · SyncMusic</h1>

<p align="center">把 <b>Navidrome</b>（或任何兼容 Subsonic 协议的服务）里的歌单与收藏，按「标题 + 歌手」模糊匹配后导入 <b>飞牛音乐（fnOS）</b>。</p>

<p align="center"><b>只动歌单，不动音乐文件</b> —— 不删除、不移动、不转码任何音频。</p>

<p align="center"><img src="https://img.shields.io/badge/version-0.1.8-blue" alt="version"></p>

---

## 它解决什么问题

很多人同时维护两套音乐系统：一套自建 Navidrome，一套是 NAS 自带的飞牛音乐。歌单和红心散落在两边，手动一首首重建非常痛苦。

音纽做两件事：

1. 读取来源歌单 → 在目标曲库找到同一首歌 → 在目标端创建同名歌单
2. 读取来源收藏（歌曲 / 专辑 / 艺人）→ 在目标端标红心


## 功能

- **歌单导入**：选择歌单 → 匹配预览 → 逐首核对置信度 → 批量写入目标曲库
- **收藏导入**：独立支线，无需选歌单；专辑与艺人收藏自动展开去重，已收藏的曲目灰显跳过
- **匹配分级**：`≥0.85` 高置信、`0.6~0.85` 疑似、`<0.6` 未匹配（未匹配不会导入）
- **匹配页全选**：左下角一键全选，跨全部歌单面板生效，兼作取消全选
- **重名歌单三种处理**：追加到现有歌单（默认）/ 自动新建副本 / 删除同名歌单后重建
- **导入日志**：整页查看逐条结果；导入结束弹应用内结果提示（成功 / 失败数）
- **连接设置**：测试按钮只做即时验证、不写配置；「保存设置并继续」自动验证两端
- **记住密码（可选）**：默认不保存，密码只在本次窗口内使用；勾选后加密落盘，重启免输入，取消勾选再保存即清除
- **明暗主题**：默认跟随系统，可手动切换
- NAS 版走飞牛统一网关（Unix Socket），不监听 TCP 端口；纯 Python 标准库实现，无第三方依赖

## 安装

下载 Release 里的 `SyncMusic_0.1.8.fpk`，在飞牛网页桌面「**应用中心 → 右上角菜单 → 手动安装**」上传，安装完成后桌面出现「音纽」图标。

## 使用

1. **连接设置**：填 Navidrome 与飞牛音乐的地址、账号；可先点「测试连接」即时确认（不会保存任何配置），再点「保存设置并继续」，工具会自动验证两端，全部通过才进入下一步
   - Navidrome：`http://NAS的IP:4533`
   - 飞牛音乐：`http://NAS的IP:5666`（即登录 fnOS 网页用的地址）
   - 需要重启免输密码，勾上「记住密码」再保存
2. **选择歌单**：勾选要搬运的歌单 → 「匹配预览」
3. **匹配与导入**：按歌单标签页核对结果（绿色高置信一般可直接要，黄色疑似自行判断），可用左下角「全选」一次选中所有歌单；选好重名处理方式 → 「开始导入」

只想同步收藏？点左侧支线的「收藏导入」，直接「读取收藏并匹配」即可。

## 打包（fnOS）

`fpk/` 目录是完整的 fnOS 应用工程，打包需在 Linux（NAS）上执行：

```bash
cd fpk
sed -i 's/\r$//' manifest config/privilege config/resource app/ui/config cmd/*
chmod +x cmd/*
fnpack build          # 产物为 SyncMusic.fpk
```

详见 [fpk打包说明.md](fpk打包说明.md)。

## 安全边界

本工具只读写**歌单**与**收藏**这类列表，所有操作都在歌单层面：

- 读取源歌单时只取歌单名与歌曲信息，不下载、不转码、不复制音频
- 导入时只创建或修改歌单，加入的是目标曲库里**已有歌曲**的引用
- 「删除同名歌单后重建」只删除歌单对象，曲库里的音频文件、目录结构、标签一律不动
- 匹配依据是两端接口返回的曲目字段（歌名、歌手），不读取音频文件本身或其标签
- 静态资源只放行图片并做路径前缀校验，全程序唯一写文件是固定路径的 config.json

最坏的结果只是某个歌单被重建（可用本工具重导），**音乐文件永远不会被本工具删除或移动**。
